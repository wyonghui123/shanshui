# D1 · 中古音韵书

> **一句话**：给全链路一张「字 → 四声(平/上/去/入) + 韵部」的**确定性查表**，让「平长仄短、入短韵长」不再靠手工标注。
> **日期**：2026-10-03 ｜ **对应**：`model_cards.md` 卡片 1（格律模型）、卡片 8（语音韵律模型）

---

## 1. 为什么要有 D1

`src/voice/voice_prosody_process.py` 里，每首诗的 `(字, 平仄, 角色)` 三元组是**手工标**的：

```python
("千", "level", "level"), ("绝", "entering", "entering"), ...
```

换一首诗就要重标一遍，且无法保证一致性。D1 把这一步变成**查表**：

| 环节 | 手工时代 | 有 D1 后 |
|---|---|---|
| 判平仄 | 逐字人标 | `readings(ch)` 查表 |
| 判入声 | 人记 | `tone == "入"` |
| 判韵脚 | 人看韵部 | `detect_rhyme()` 由句末字反推 |
| 生成三元组 | 手写 | `analyze()` 输出 `(字, tone, role)` |

D1 属**确定性数据层**（"能查表的绝不交给模型"），与卡 1「格律解析」的分工是：**D1 给选项，卡 1 做消歧**。

## 3. 数据 schema（`d1_rhyme.json`）

```jsonc
{
  "meta": { "standard": "平水韵（106 部）", "counts": {...}, "source": {...} },
  "rhymes": {
    "七陽": { "rhyme": "七陽", "rhyme_full": "下平聲七陽", "tone": "平",
              "tone_group": "下平", "seq": 7, "n": 268 }
  },
  "chars": {
    "东": [ { "tone": "平", "tone_group": "上平", "rhyme": "一東",
              "code": "level", "src": "上平聲一東", "trad": "東" } ]
  },
  "t2s": { "東": "东" }          // 繁体 → 简体，供繁体输入归一
}
```

**设计要点**

- **索引键用简体**（与 `context.json`、诗文本一致）；每条读法带 `trad` 回溯源字形。
- **一字多读**全部保留（`chars[ch]` 是数组）：这是 D1 的**核心价值**——选项档位必须覆盖实测值。
- `code` 直接给出 `src/voice/voice_prosody_process.py` 要的 `level/oblique/entering`，免二次映射。
- `t2s` 让解析器**无需运行时依赖 zhconv**（转换只在构建期做一次）。

## 4. 怎么用

```bash
# 构建（需构建期依赖 zhconv；产物自包含）
python src/d1/d1_build.py

# 回归校验：韵脚识别 + 与手工标注逐字比对
python src/d1/d1_resolve.py

# 覆盖率护栏：20 首常见近体诗
python src/d1/d1_covcheck.py

# 直接对一首诗出三元组
python src/d1/d1_resolve.py --lines "千山鸟飞绝|万径人踪灭|孤舟蓑笠翁|独钓寒江雪"
```

解析器接口（`src/d1/d1_resolve.py`）：

| 函数 | 作用 |
|---|---|
| `readings(d1, ch)` | 字的全部读法（自动处理繁体） |
| `tone_options(d1, ch)` | 平仄选项集，如 `{'平','仄'}` |
| `detect_rhyme(d1, lines)` | 由句末字反推韵部 + 押韵句号 |
| `analyze(d1, lines, meter=False)` | 逐字 `(tone, role)`；`meter=True` 启用「二四六分明」消歧 |
| `meter_fill(...)` | 偶数位平仄交替，消歧兼平仄字（属卡 1） |

## 6. 缺口与边界（重要）

| 缺口 | 说明 | 现状 |
|---|---|---|
| **兼平仄字需消歧** | 望/过/不/思/乡/间 等一字多读；落在**一三五不论**的奇数位时格律无法判定 | D1 **只给选项**并标 `ambiguous`；偶数位用「二四六分明」可解，奇数位须靠 `context.json` 或频次先验 |
| **源数据漏收常用字** | 源抓取不全（如 啼、爐/炉、葡、遍 缺） | 已建 `d1_supplement.json` 补遗层（4 字，逐条给据）；**宁缺毋滥** |
| **总量小于最全韵表** | 本表收 8313 字；文献载最全平水韵约 1.15 万字（平 4719 + 仄 6857） | 目标域（唐律绝常用字）覆盖 100%，生僻字覆盖有限 |
| **简体归一可能合并异体** | 繁体→简体多对一（如 發/髮→发）会合并选项集 | 保留 `trad` 字段可回溯；合并处自动进入 `ambiguous` |

**不做的事**：不把 D1 当"消歧器"；不用现代普通话拼音反推中古音（声调已变）；不猜补无据的字。

## 7. 升级路径

1. **加源合并**：接入《广韵》全字表（206 韵，约 2 万字）作第二源，按「平水韵优先、广韵补充」合并，主要补生僻字。
2. **频次先验**：给兼平仄字附「近体诗用读频次」，让奇数位消歧有据（当前靠默认取平）。
3. **句式谱匹配**：把卡 1 的「二四六分明」升级为完整 4 句式（平起/仄起 × 入韵/不入韵）匹配，并处理折腰体等变体。
4. **接 `context.json`**：把 `prosody.pingze` 与 D1 生成结果做交叉校验，差异入 `gaps` 队列。
