# 图声要素的数据可得性与模型映射

> **问题**：`图声表达要素补遗.md` 与 `model_cards.md` 里的这些要素——**能不能从诗和文本里直接得到？**
> 得不到的话，**还缺什么数据**才能确定？**由什么模型**来确定？
> **日期**：2026-10-03 ｜ **范围**：卡片 1–9 + 补遗 §1（图）/§2（声）/§3（跨模态）

---

## 0. 一句话结论

**诗与文本给的是「输入端」，不是「要素」本身。**

- 诗能直接给的：**字词、意象名、格律骨架、时空词、否定词、情感线索**。
- 要素（皴法 / 三远 / 配器 / 声景 / 墨色 / 留白率 …）**都是「意象 × 映射」的结果，诗里没有**。
- 所以要确定要素，缺的**不是算法，是 4 类桥接数据**（详见 §3）：
  1. **中古音韵书**（字 → 平/仄/入/韵）
  2. **意象—画法映射表**（意象/情感 → 三远/皴法/墨色/构图）
  3. **意象—声法映射表 + 音源库**（意象/情感 → 声景/配器/静默/音质）
  4. **情感—韵味锚定集**（V/A/T、24 品的人工标注）
- **模型分工铁律**：能查表的绝不交给模型；查不到的才用 LLM；有物理/约束的用求解器。
- **「模型是怎样的」其实已有答案**：意象链的真模型在 `src/o2/o2_imagery.mjs` 用 `[PLUG]` 钉死——①分词 `T15 TopWORDS-Poetry`（格律先验）②意象 `C1 Albert-BiLSTM-MHA-CRF` ③消歧 `B2 UD-Kanbun`；现为「词典+规则」替身，接入后 schema 不变（详见 §6.3）。**所以缺的不是模型，是喂给模型的数据。**

## 1. 可得性三层（先把要素分档）

| 档 | 含义 | 要素举例 | 确定手段 | 自动化 |
|---|---|---|---|---|
| **L0 诗内直取** | 诗的字词/格律里就有 | 意象名、平仄、入声、韵脚、时空词（雪/朝/暮）、否定词（绝/灭） | 查表 + 规则，**确定性** | 高 |
| **L1 桥接可得** | 诗给「因」，需一张映射表得「果」 | 三远、皴法、墨色、留白率、声景、配器、静默、情感预设 | **桥接表**（需人建）+ 规则/求解器 | 中 |
| **L2 外部/人工** | 诗里完全没有，需语境或人工裁定 | 文化极性、用典、韵味 24 品、有我/无我、声画对位 | 语境资料 + LLM + 人工 | 低 |

> **关键判据**：一个要素属于哪档，看它**是不是诗中名词的直接翻译**。
> 「孤舟」→ 画个舟，是 L0；「孤舟」→ 用**中锋一次落笔、墨 0.92**，是 L1（需笔墨表）；「孤舟」→ **孤傲而非凄惨**，是 L2（需文化极性）。

### 2.4 语境资料的「卡片级挂钩」（本次核查新发现）

`context.json` 不只是散装背景——它已经有**按卡片编号的挂钩**和**共识裁决字段**：

| 字段 | 内容 | 喂给谁 |
|---|---|---|
| `pipeline_implications` | `card_1_prosody` … `card_9_selfcheck`，逐卡给出「语境 → 该卡」的结论 | 卡 1–9（直接挂钩） |

> **含义**：「语境 → 卡片」的桥**已经搭了，但只搭了三首（手工）**。把它固化成 schema，比新建 D2 更省力，收益也直接。

## 4. 模型架构（诗 → 要素 的推导管线）

```
         ┌─────────────── L0 抽取（确定性）───────────────┐
诗文本 ──┤  字词 · 意象 · 格律 · 时空词 · 否定词 · 情感线索  │
         └───────────────────┬───────────────────────────┘
                             │
语境资料 ────────────────────┤
(context.json: 系年/境遇/      │
 用典/解读/格律)              ▼
                    ┌─────────────────────────────┐
                    │  桥接层 ★ 主要缺口（需建表）    │
                    │  意象/情感  ×  D1/D2/D3 映射表 │
                    └───────────────┬─────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
 [L1 生成]                  [L1 生成]                    [L2 裁定]
 构图约束优化              语音 DSP / 音源混音            LLM 判韵味/境界/对位
 笔墨物理(t^0.5)            (静默层·声景层)                ← 人工锚（语境资料）
        │                           │                           │
        └───────────────────────────┼───────────────────────────┘
                                    ▼
                    ┌─────────────────────────────┐
                    │  卡9 护栏（自检）             │
                    │  ECE · 留白率 · 静默预算 ·    │
                    │  负节点 · 韵律-运动耦合        │
                    └─────────────────────────────┘
```

**四类模型的分工**：

| 模型类型 | 解决什么 | 要素举例 | 为什么不用别的 |
|---|---|---|---|
| **查表 / 规则** | 有明确判据的离散映射 | 格律、四时、装裱、声情 | 确定性可解，交给模型是浪费且不可复现 |
| **约束求解器** | 多约束下的最优布局 | 构图、留白、视觉重心 | 目标函数明确，可求最优 |
| **物理 / 信号处理** | 有物理律的过程 | 笔墨扩散 t^0.5、语音规整 | 有解析式，不猜 |
| **神经模型（LLM/TTS/VLM）** | 非它不可处 | 韵味/境界判读、语音合成、当裁判 | 语义/审美无法写死规则，且需护栏 |

> 呼应项目既有教训：**模型不是稀缺资源，「把模型接进链路」所需的数据表才是瓶颈。**

## 5. 结论与建议（按依赖关系排，不按重要性）

| 顺序 | 补什么 | 理由 | 依赖 |
|---|---|---|---|
| **① 先做（并列）** | **D1 中古音韵书** | 它是 `[PLUG]①分词 T15 TopWORDS-Poetry` 的**前置输入**（格律先验），是整条链的**第 0 步**——没有它，新诗连分词都进不了真链路 | 无 |
| **① 先做（并列）** | **D2 意象—画法映射表** | 图侧全部 L1 要素的共同上游；成表后三远/皴法/墨色/留白可**批量取值** | 无 |
| **② 顺手做** | **固化 `context.json` schema** | `pipeline_implications` 已手工跑通三首，把它变成规范：边际成本最低、收益直接 | 已有三首样本 |
| **③ 后做** | **D3 声法表 + 音源** | 从 0 到 1 的资产，最重；且需先有 D2 的「意象→要素」范式。**三首示范已落地（2026-10-05）**，均按同一秤取值 | D2 的范式 |
| **④ 最后** | **D4 情感锚定集** | 属「天花板」（韵味/情感），需前三层稳定后再调 | ① 的度量闭环 |

**三首现状快照**：
- **L0**：基本齐（格律已手工标，意象词典已有）。
- **L1**：**部分**——构图/笔墨/语音已实现，但映射表零散、不成表（换诗即失效）。
- **L1（声侧）**：**三首均落地**——三张声法表 + 采样/合成音乐轨已接入动画（含 ducking）：江雪羽调·古琴+箫、白帝城徵调·笛+琴点缀、静夜思宫调·箫+琴轻点。
- **L2**：靠 `context.json` 撑住（用典/解读/极性已挂源）。

> **一句话**：三首能跑，是因为**手工替桥接层打了补丁**；要让第 4 首、第 40 首也能跑，缺的就是 **D1 + D2 两张表**。
