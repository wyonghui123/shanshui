字体 · 表达要素研究报告

文字的字体如何成为画面的一部分 —— 现状盘点 · 书体谱系 · 落款规矩 · 可商用字体库 · 落地路径

本报告回答一个问题：在「水墨 · 三首绝句」项目里，字体算不算一个「比较大」的表达要素，以及它由哪些可参数化的维度构成、现在做成了什么样、下一步怎么改。

结论先行：字体是唯一同时横跨「构图 / 笔法 / 时间」三层的要素——它占画面的位置（章法）、它与皴法笔调的统一（笔墨）、它逐句写就的节拍（时间化题跋）。因此它不是装饰，而是表达要素本身。项目原状是「题诗用系统楷体、印章用宋体」，存在两个具体缺口：跨平台不确定性、印章不合「印从篆出」的惯例。两处均已落地——题诗改为内嵌自持子集（七款书体：楷 / 行楷 / 行 / 隶 / 草，跨平台一致，篆隶楷行草谱系齐备）；印章改用篆书子集（敬峰中山王篆，依 OFL §3 改名 PoemSeal，动画与三张全链路页均已内嵌）。

依据：王岳川《书法灵韵》· 谢赫六法 / 荆浩《笔法记》· 历代题款与钤印通例 · 苏轼「诗画本一律」
互链：表达要素总纲 · 图声表达要素补遗 · 人物造型语法 · 日期 2026-10-04
§0

结论速览

① 字体是「大」要素

同时耦合构图（题跋位置/章法）、笔法（与画意统一）、节奏（逐句题诗＝题跋的时间化）。已在总纲 §1.7 被点名为构成的一部分，但未展开。

② 原状 2 个缺口，均已闭合

题诗＝系统楷体（跨平台会飘）→ 已改内嵌自持子集；印章＝宋体（不合「印从篆出」）→ 已改篆书子集。前者是确定性问题，后者是语义问题，现已分别解决。

③ 可改，且成本可控

OFL 授权的水墨气质字体已齐备；本项目字符集极小（三首绝句＜100 字），子集化后只有几十 KB，可内嵌。
一个结构性发现：当前「逐字写出」其实是 clipPath 高度增长的揭示，不是真正的笔顺书写。要「书写感」必须换成 path 字形 + 描边动画——这是字体要素从「排版」升级为「书写」的分水岭（§6）。

§2

字体作为「表达要素」的分解（9 个可参数化维度）

把「字体」拆成可下参数、可断言、可回改的维度——这样才能像 layer_technique 那样进入规则体系，而不是一个笼统的「好看 / 不好看」。

维度含义可参数化项目现状
1 书体篆 / 隶 / 楷 / 行 / 草，以及印刷体（宋 / 楷 / 仿宋）枚举档已落地 题诗楷 / 行楷 / 行、印章篆、草档柳建毛草；隶为谱系占位
2 结体字形骨架：方正 / 修长 / 扁方 / 欹侧随书体定未控
3 笔法起收、提按、方圆、藏露、粗细对比随书体定未控
4 墨色浓 / 淡 / 枯 / 润 / 飞白可（数值）有 题诗固定 #161616，未分档
5 字号正文 / 落款 / 标注的主次可（数值）部分 仅一个 fontSize
6 字距 / 行距字距（charPitch）、列距（colPitch）＝疏密可（数值）有 PL.charPitch / colPitch
7 排列竖排右起（传统）／横排枚举有 竖排、右起、逐列
8 书写节奏落笔顺序与速度，与配音同步可（时间序列）有 pitch / dur 逐句数组，末字韵脚恰在句末
9 印章字体（篆）· 朱文 / 白文 · 大小 · 位置枚举 + 数值部分 有印位/印面档（G8），字体未做
为什么说「比较大」：9 个维度里，书体决定气质、章法（字号/字距/排列）参与构图、节奏绑定时间轴、印章既是字又是印——一个要素同时落在构图、笔墨、时间三条链上，这在画面要素里是罕见的。
§3

书体谱系与气质（古典依据）

每种书体自带一套「形—气」对应，可直接作为「书体档」的语义依据。

书体形气 / 用途依据
篆线条圆转、结体纵长、图案化装饰古拙、金石、庙堂感；印章专用书法灵韵（人民网）
隶化曲为直、变纵为横、字形扁方、蚕头燕尾端庄、舒展、汉碑气象王岳川《书法灵韵》（全国哲社办）
楷字形方正、横平竖直、一笔不苟法度、端正；题款最稳《书法字体》百科 / 北大书法所
行楷草之间、牵丝映带流畅、活泼、易识；落款最常用雅昌《中国画题款艺术的形式美》
草省并连绵、一笔而下奔放、难识；不宜作落款同上（落款通例）

细档楷书四大家：同为楷，气质不同

书家风格关键词
颜真卿宽博浑厚、气势开张「颜筋」· 端庄雄伟
柳公权瘦劲严谨、法度森严「柳骨」· 清健遒劲
欧阳询中宫收紧、险绝欧体 · 严谨
赵孟頫圆润秀雅、流丽赵体 · 温润
对项目的意义：同是「楷」，颜 / 柳 / 欧 / 赵 的气质差异，足以让《江雪》的瘦硬与《早发白帝城》的开张用不同楷档区分——「书体档」不必是「篆隶楷行草」这么粗，也可以是「楷·瘦硬 / 楷·宽博」。

§6

技术落地：体积 · 竖排 · 内嵌 · 真书写

A体积：中文字体大，但本项目极小

整套中文字体动辄数 MB，但本项目字符集只有三首绝句（＜100 字）。按实际用字做子集化，可压到几十 KB，直接内嵌交付物。

# 按诗句字符集做子集（示意）
pyftsubset LXGWWenKai-Regular.ttf \
  --text-file=poem_chars.txt \
  --flavor=woff2 --layout-features='*' \
  --output-file=wenkai_poem.woff2

B竖排：用 writing-mode，不用手工堆坐标

传统竖排右起对应 CSS writing-mode: vertical-rl（CJK 从上到下、列从右向左）。当前项目是手算 colX / baseY 逐字定位——功能等价，但换成 vertical-rl 可让浏览器接管断行与标点挤压。

.poem{ writing-mode: vertical-rl; text-orientation: upright; letter-spacing:.08em }

C内嵌：@font-face + 子集，摆脱系统字体名

@font-face{
  font-family:"PoemKai";
  src:url("wenkai_poem.woff2") format("woff2");
  font-display:swap;
}
.poem{ font-family:"PoemKai","STKaiti",serif }   /* Web 字体优先，系统体兜底 */

D真书写：从「揭示」升级为「笔顺」 已落地

现状：题诗已从 clipPath 矩形自上而下长高（「被揭开」）升级为 path 字形 + 逐笔中线遮罩（「被写出」）。每字取自持字体的字形轮廓作 <path>，被一条 <mask> 遮住；mask 内按笔顺铺若干条「笔锋带」（中线按笔画长度加粗），用 stroke-dashoffset 逐笔展开，末笔走完即字形写就。
方案做法代价 / 适用
保持揭示clipPath 高度增长零成本；有「显影」感，无「书写」感。已弃用（保留为数据缺失时的降级）
整字描边字体转 path → 轮廓描边动画中成本；像「描红」，笔画顺序不真
逐笔书写 已落地按笔顺拆中线，逐笔 dashoffset高成本（需笔顺数据）；最接近真书写
数据与出处：笔画顺序与中线（运笔轨迹）是字体里没有的，取自 hanzi-writer-data@2.0.1（源自 Make Me a Hanzi，Arphic Public License）；字形轮廓取自本项目自持字体子集。两者在 build/stroke_data.py 里合并：中线换算到设计单位（upem=1000）并按 RDP 简化，再对每字的轮廓边界点算「逐笔遮罩带宽」（每个边界点归属最近中线，取该笔内最远点 × 安全系数），保证末笔走完时笔锋带的并集恰好铺满字形而不串笔。产物 dist/animation/strokes.js（window.POEM_STROKES，64 字 / 3 字体）。
