§1

控制链总图

从「一首诗 + 一批数据源」到「一幅水墨成画」，中间是一条五段式控制链。每段有明确的输入、输出与归属：抽取段把原料变成结构化节点，D2 段把节点翻译成技法档位与区间，求解段把区间收紧为精确值，落地段把数值渲染成画面，验收段只读校验、不回写参数。

2.1 向上推演：数据缺口清单（§5.5 工单的上游溯源）

§3

抽取与处理段

本段把五类原始输入转成下游可用的结构化中间件。三条支线并行：意象抽取（O2）、格律标注（D1）、语境→卡约束。

O2 意象抽取

分词 → 抽取 → 消歧 → 可画性门控。产出 o2_imagery.json：每个意象节点带 channel（v / x）· conc（确信度）· gate.class（实写 / 虚写 / 不可实写）· layer_hint（景深）。这是 D2 的主要输入。

D1 格律标注

查平水韵字典，标注逐字声 / 韵 / 平仄与韵脚。产出 d1_rhyme.json。服务语音链为主，其「入声密度 → 基调」结论供入画链的语气约束引用。

context → 卡约束

把 pipeline_implications 逐条挂到卡1–卡9：如 card_2_imagery「孤舟 / 蓑笠 / 独钓 = 孤傲 · 隐逸，不是凄惨」直接改写意象极性，进而改 D2 的墨 / 底色偏置。

一条纪律：抽取段只做「结构化」，不做「裁定」。意象是否可画、格律如何标注，都有明确判据；但「这首诗该是什么气质」这类判断不在此段，而交由轴1 的 12 算子判档（见 《立意与品格的可度量方法》）。抽取段越界裁定，会让下游失去可追溯的判据来源。
§4

D2 控制引擎（核心段）

本段是全链的枢纽：把「意象类别 + 情感 + 景深」翻译成「技法档位 + 候选 + 区间」。引擎由四张表构成，逐层收窄——vocab 定可选空间，class_defaults 给类别默认档，modulators 按上下文派生调整，rules 最后做护栏过滤。§4.3 逐一细化解剖十七器（十器 + C 组七器），并标出各自「已建模但未接线」的部分。

为什么验收不回写。O1 是「护栏」而非「目标」——它的职责是防止改坏，不是驱动改好。若让验收结果反向调参，等于用「像不像」倒逼「画什么」，会把项目拖向追 SOTA 的图解化路线。验收段只输出结论，调参由上游（D2 / 求解器）按判据决定。
§7

生成可控性分层（L1–L4）

控制链回答「谁在哪一段动手」，本层回答「一个要素到底能不能被拧」。这与总纲的 M0–M3（能不能读数）正交：同一个 M1 里，既有可设的旋钮，也有只能读的仪表。把两者分开，才知道哪些要素真能当生成参数、哪些只能作验收。本节即总纲 §3.4 的展开，且为 L1–L4 的唯一真源。
