§0

结论先行

一句话。轴1 之所以此前停在 M2，是因为把「立意」和「品格」当成了一件事、又把「品格」当成了一维阶梯。拆开之后：品格是可测的（二维平面上的坐标），立意也是可测的（但测的不是画面，是计划的可追溯性）；真正不可测的只有气韵——而这条分界古人早就划过。
古证（本报告的理论支点）。郭若虚《图画见闻志·论气韵非师》：「六法精论，万古不移。然而骨法用笔以下，五者可学。如其气韵，必在生知，固不可以巧密得，复不可以岁月到。」
古人的划分是：气韵＝生知（不可学），其余五法＝可学。品格（逸神妙能）评的正是「可学部分」的高下——故可判、可测、可训；气韵是「生知部分」——故不可测、不可训。
这不是我们的推断，是原文的推论：可学者可度量，生知者不可度量。轴1 因此天然分两半——「品格」这一半落在可测区，「气韵」那一半（轴0）留在 M3。

0.1 三条被推翻的旧假设

旧假设为何不成立修正
「品格是一维阶梯：能 < 妙 < 神 < 逸」四格不是同一条线上的四档——逸格要求「简且具」，能格要求「繁且具」，是两个约束而非一个刻度。一维化会丢掉「逸格为何最难其俦」。改为二维平面（简繁 × 形具）
「品格只能靠 LLM / 人工判读」四格的定义原文里全是可数词：「笔简」「形具」「墨妙」「形象生动」。判读之所以需要，是因为没把定义拆成算子。拆成 12 个可计算子
「立意太虚，无从度量」立意是「诗 → 参数档」的计划，不是画面属性。计划的可追溯性、覆盖率、一致性都是可数的。改为测计划三率
§1

先拆对象：立意 ≠ 品格

此前把两者混为一谈，是轴1 卡在 M2 的第一个原因。它们在链路里的位置根本不同——一个是上游的计划，一个是下游的呈现。度量对象不同，方法自然不同。

立意（意）＝ 计划

「意在笔先」——它是落笔之前的那张图纸：这首诗该是什么气质档、该走哪条链。
它在链路上的位置＝ 诗 → 语境资料 → 参数档。
故它不是画面属性，不能从画上量；能测的是这个计划的可追溯性、覆盖率、一致性。

度量对象：映射 f : 诗 → 参数档
度量手段：溯源检查 / 覆盖统计 / 一致性约束
品格（格）＝ 呈现

它是画出来之后的气质：逸 / 神 / 妙 / 能，南宗 / 北宗，雅 / 俗。
它在链路上的位置＝ 参数档 → 画面。
故它是画面属性，可从冻结场景的矢量基元直接量取。

度量对象：映射 g : 画面 → 品格坐标
度量手段：从 scene.json 矢量基元算算子
为什么这个拆分重要。若把「立意」当画面属性去测，永远测不出（它不在画上）；若把「品格」当主观判断去测，就白白放弃了它定义原文里的可数词。拆对对象，两半立刻都可测。
§2

品格是二维的，不是一维阶梯

黄休复《益州名画录》四格的原文定义，逐条拆开就会发现它们落在两个轴上：简繁（笔简 ↔ 繁密）与 形具（形具 ↔ 形失）。逸与能都在「形具」这一端，却分居「简」「繁」两极——所以一维排序必然自相矛盾。

2.1 四格原文 → 两轴坐标

格原文（黄休复《益州名画录》）简繁轴形具轴可数词
逸格「画之逸格，最难其俦。拙规矩于方员，鄙精研于彩绘，笔简形具，得之自然，莫可楷模，出于意表。」极简 ←→ 具笔简 · 形具 · 鄙彩绘
神格「大凡画艺，应物象形，其天机迥高，思与神合，创意立体，妙合化权。」中→ 具思合 · 立体（结构完整）
妙格「画之于人，各有本性。笔精墨妙，不知所然。若投刃于解牛，类运斤于斫鼻。」任意（偏中）中笔精 · 墨妙（墨阶丰富）
能格「画有性周动植，学侔天功，乃至结岳融川，潜鳞翔羽，形象生动者。」→ 繁→ 具形象生动（形似度高）

2.2 平面图（四格定位 + 病区）

横轴＝简繁度（左简右繁），纵轴＝形具度（下失上具）。逸格在左上角——要求同时满足「极简」与「形具」两个约束，这正是它「最难其俦」的几何解释：它是唯一需要两约束同时成立的角，而其余三格各只需一个半。

黑点＝下方计算器实时算出的「当前画面」坐标。平面按三条横带分区（与 §4.2 判档规则一致，v1.1 修）：顶带 y≥0.70＝形具，按简繁分逸 / 神 / 能（逸与能同高不同宽，一简一繁）；中带 0.50≤y<0.70＝妙（技法之德，不限简繁）；底带 y<0.50＝病——形失则无论简繁皆落病，这正是「谨细」（张彦远「精之为病也，而成谨细」）与「邪甜俗赖」的位置。

几何解释「逸格最难」。逸格位于左上角，需要「简」与「具」同时成立——这是二维平面上的一个角点，不是一条线上的位置。而能格只要「繁且具」（顶带右段），神格只要「中且具」（顶带中段），妙格只要「中形具」（中带整条，不限简繁）。所以逸格的稀缺是结构性的，不是「更高一档」的主观排序。这也解释了为什么黄休复要把它从朱景玄的「神妙能逸」（逸在末）提到首位（逸在首）——不是抬高，是换了一套坐标系。

下面每个算子都满足三条：① 只读 data/source/scene/<pid>.json（与 scene_assert.py 同一数据源，无需栅格化）；② 有古典定义原文对应；③ 有明确公式。可度量档按总纲的 M0–M3 标尺标注。

与计算美学文献的对照（旁证）。上述算子并非自创，多数在计算美学里已有对应：简繁度对应 Fan 等「视觉复杂度」研究（色彩丰富度 / 笔触粗细 / 留白三属性）；墨阶熵对应灰度直方图熵；刚柔比对应笔触方向直方图与曲率分布；雅度对应对称度 / 色彩丰富度 / 重复度；留白率对应 Liubai 框架的负空间度量。差异在于：本报告把每个算子都锚定到一条古典原文判据，而非仅凭统计直觉——这样算出来的分才有「为什么是这个值」的解释力。

§5

立意的度量：三率

立意是「诗 → 参数档」的计划，故测计划本身，不测画面。三率全部可从现有工件算出，且都指向同一个风险：计划漂移（模型自由发挥、参数无出处）。

指标定义 / 公式回答什么问题数据来源
T 可追溯率 T = 带 data-d2 且可追到语境资料的参数数 / 总参数数 每个参数档「有没有出处」——防模型拍脑袋 pipeline data-d2 + d2 快照
Cᵢ 意象覆盖率 Cᵢ = 画面有对应元素的视觉意象数 / o2 抽出的视觉意象总数 「诗里的意象有没有都落地」——防漏画 o2_imagery.json ↔ scene 层
A 基调一致率 A = 与目标品格档不矛盾的轴数 / 总轴数（如逸格 ↔ 简笔 ↔ 高留白 ↔ 淡墨，背离即扣） 「各轴的调子有没有跑偏」——防自相矛盾 D2 各轴现算值 + 品格档
立意的度量哲学：测「计划」不测「画」。把立意当画面属性去测必然失败（它不在画上）。但计划的三率是可数的：有出处、全覆盖、不矛盾。这三条恰好对应项目最怕的三件事——自由发挥、漏要素、调子打架。所以立意度量不是学术摆设，是现成的护栏。
迁想妙得的落点。顾恺之「迁想妙得」＝先代入（迁想）再得神（妙得）。在链路里，「迁想」＝读语境资料并形成基调假设，「妙得」＝落到参数档。故 T（可追溯率）其实就是「迁想有没有留下痕迹」——一个参数档若能追到具体语境资料，说明它是「想」出来的而非「凑」出来的。
§6

效度：怎么证明这些代理指标是有效的

这是本报告最关键、也最容易被跳过的一节。上面 12 子都是代理指标（proxy）——它们能不能代表「品格」，本身需要一个元度量来验证。否则就是「自己造指标、自己判合格」。

① 人工量表

请 2–3 位懂画者对判读帧各打四格分（1–5），取均值作基准真值。

② 相关检验

算代理分与人工分的 Spearman ρ；ρ ≥ 0.7 视为有效，否则调权重或弃用该子。样本单位＝判读帧，n ≥ 20（见下）。

③ 区分度检验

三首应落在不同区（江雪→逸、白帝城→神、静夜思→逸/妙）。若三首都挤在同一点，说明算子无区分力。

样本单位不能是「三首」（v1.1 修）。v1.0 拟以三首诗为样本算 Spearman ρ——n＝3 时相关系数几乎没有统计意义（ρ≥0.7 的阈值形同虚设，三点几乎总能连成一条单调线）。正确做法是把判读帧当作样本单位：项目现有 14 帧生成图 / O1 的 57 道判读题，天然提供 n≥20 的样本；也可让每首诗出多个「品格档变体」（如江雪按逸/妙各渲一版）以扩充样本。②与③分工：②管「算得准不准」（相关），③管「分得开不开」（散点），二者都不可省。
为什么必须先做效度。项目已有教训：评估工具的缺陷会导致错误结论（选项粒度缺口、判读帧未绑定、题面歧义）。品格度量若跳过效度检验，就会重演同一类错误——只是这次错在「度量方法」这一层，比错在「度量结果」更难发现。

§8

边界与诚实声明

仍然不可测的，只有气韵。本报告把轴1 的「品格」推进到了可测，但没有、也不能把气韵拉进来。原因有古证（郭若虚「气韵必在生知」），也有工程理由：气韵是笔法 / 墨气 / 丘壑三者的涌现结果（龚贤「三者得而气韵生矣」），它没有独立旋钮。把品格可测误当成气韵可测，是本方法最大的误用风险。
项可测性说明
品格档（逸神妙能）可测二维坐标 + 门限；但需人工量表校准效度（§6）
南北宗 / 刚柔可测方向与折角的统计；注意：董其昌原论「渲淡 / 钩斫」是笔法二分，我们的 R 只是其可算代理
雅俗可测（代理）饱和度 / 色相数 / 对称 / 重复的合成；「雅」无公认真值，仅作相对比较
立意（计划）可测三率；测计划不测画
气韵生动不可测M3；只作 O1 验收，不作生成参数——本报告不改变这一结论
「逸格是否真比能格好」不判本方法只判落在哪个区，不判哪个区更高——高下是审美立场，不是度量问题
三条方法论护栏。① 代理指标必须报「效度」，不得只报数值；② 阈值是初值，随量表校准更新，不得当成真理；③ 判档只回答「在哪」，不回答「多好」——避免把度量变成新的图解化压力（与项目「不为追要素全中导致画面图解化」同源）。
