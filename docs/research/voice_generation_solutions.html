语音生成方案深化研究

《静夜思》配音：商用云 API · 开源本地模型 · 诗歌专用合成，三线并行的最新全景与落地建议

方法：三条并行证据线（商用云 API · 开源本地模型 · 诗歌专用合成与实战工作流）→ 关键事实二次核验 → 与前期「情感 / 抑扬顿挫 / 性别匹配」及「吟诵 / 韵律后处理」研究衔接。置信标注：[CONFIRMED] 多源 / [SINGLE-SOURCE] 单源 / [unverified] 未核实。
摘要

三条线的诊断结论

结论：商用 API 已足够满足「情感 + 男声 + 句级抑扬顿挫」；开源本地出现 2025-12 新强者；诗歌专用合成仍是空白，但有一个意外发现。

商用云 API
● 成熟可用

男声 + 情感 + 句级韵律全部现成。火山擎苍 2.0 原生支持 悲伤 + 旁白-沉浸；Azure 有 poet / lonely / whispering 风格；阿里 CosyVoice v3.5 支持指令式控制。

开源本地模型
● 新强者出现

Qwen3-TTS（2025-12，Apache-2.0）支持描述式音色设计 + 3 秒克隆 + 指令控制，可商用；CosyVoice 3 的 instruct 可控制情感 / 语速 / 音量。本地路线首次具备与商用 API 相近的灵活性。

诗歌专用合成
● 空白，但有新线索

Intoner（IJCAI 2025）仍未开源；但阿里云 CosyVoice 系统音色列表中出现了「诗词朗诵」类别、含「李白（古代诗仙男）」预设——需要实测验证效果。

关键红线

克隆真人声音（叶嘉莹 / 蒙曼 / 康震等）用于公开传播属高风险。《民法典》第 1023 条：对自然人声音的保护，参照适用肖像权保护的有关规定——未经同意克隆、使用特定自然人声音可能构成侵权。[cite:11][cite:12]

总体判断

「模型不是稀缺资源，接入链路的能力才是瓶颈」这条项目经验在此完全成立：语音生成的原料（模型/API）已经过剩，缺的是把「情感 → 男声 → 句级抑扬顿挫 → 逐字平仄」串起来的链路。逐字平仄依然是任何生成模型的天花板，韵律后处理链路（前期研究）的必要性不减。

推荐

本地首选 Qwen3-TTS（描述式音色设计 + 指令控制 + Apache-2.0 可商用 + 中文一流）；备选 CosyVoice 3（0.5B 轻量、instruct 情感控制，但许可需按项目页核实）。若已有自录样音想固化成稳定音色，GPT-SoVITS 的少样本微调最顺手。

一致的局限

本轮检索的所有开源模型与商用 API 一样：均未提供「逐字音高/时长」的显式控制（即五言诗每个字单独定平仄）。情感控制要么靠指令文本、要么靠参考音频——这正是前期「韵律后处理链路」继续成立的原因：生成器负责「对的情感 + 对的男声」，后处理负责「对的平仄」。逐字控制缺口（一致）

法律红线：声音克隆受《民法典》约束

「对自然人声音的保护，参照适用肖像权保护的有关规定。」 — 《中华人民共和国民法典》第一千零二十三条第二款 [cite:11][cite:12]
  • 最高法院法答网明确：民法典关于肖像权权能、禁止侵害、合理使用、商业利用的规定，均可参照适用于自然人声音权益。[cite:12]
  • 因此：克隆叶嘉莹 / 蒙曼 / 康震等真实人物的声音来读诗，即使非商业用途也建议取得授权；GPT-SoVITS 官方条款同样禁止未经同意冒充个人。CONFIRMED
  • 安全替代：克隆自己录的样音、或使用虚构/平台预设音色（如 CosyVoice「李白」预设——注意这是平台合成音色，非真人）。
04

《静夜思》配音综合推荐路线

与前期研究衔接：生成器（本文）负责情感/男声/句级起伏，韵律后处理链路负责逐字平仄，自录样音作为「韵味基准」。

第 1 步

商用 API 快速出样（半天内）

三条并行出样：火山擎苍 2.0（sad + narrator_immersive）、Azure Yunyi-poet / Yunhan-lonely（免费额度内）、阿里 CosyVoice v3.5（instruct 写「低沉缓慢、古诗词朗诵」+ 试「李白」诗词音色预设）。每样出整首，人工盲听裁决音色气质。

优点：零部署、逐句可精调、成本个位数人民币。

缺点：仍受「逐字平仄不可控」限制。

第 2 步

（可选）本地 Qwen3-TTS 或 CosyVoice 3

若需要离线/可复现/免 API key，部署 Qwen3-TTS（描述式音色：低沉男声、思念、缓慢）或 CosyVoice 3（instruct）。产出的男声情感底料与商用 API 同规格，供后处理共用。

优点：Apache-2.0 可商用、可版本化、无按量成本。

缺点：Qwen3-TTS 需 24GB 显存；CosyVoice 3 许可需核实。

第 3 步

韵律后处理叠加（衔接前期研究）

对选定底料执行「平长仄短 + 入短韵长」时长改写（安全区操作），必要时加「平低仄高」音区平移与韵脚拖腔。工具的 PSOLA / WORLD 依赖已在本机安装验证完毕。

优点：唯一能逼近逐字平仄的路径。

缺点：需逐字核验声调未失真；属自研投入。

第 4 步

自录样音作基准（可选，1 小时）

按「一本九法」自录一版，作为听测的「韵味上限」参照，同时可用于 GPT-SoVITS 克隆固化成稳定音色（无版权风险）。

优点：无版权风险、提供唯一真实韵味基准。

缺点：质量依赖录音环境。

顺序建议

先做第 1 步（半天），用听测决定后续。若商用 API 的情感+男声已够「情感与抑扬顿挫」，则第 3 步后处理可只做最轻档；若仍觉「没韵味」，再加第 4 步自录基准与第 2 步本地模型。每一步都可度量、可回归，符合项目「先可度量再可规模」的原则。

05

证据缺口

  • 「诗词朗诵」音色预设效果未验证。CosyVoice 音色列表的「李白（古代诗仙男）」来自平台页面，无实际朗读效果 demo 可查。待实测
  • Azure 中文表达风格稳定性存疑。有社区报告 express-as 在部分中文音色上响应不稳定，官方未否认也未确认。SINGLE-SOURCE
  • CosyVoice 3 许可证存在口径冲突。代码仓库 Apache-2.0 与 PyPI GPLv3 标记并存，商用前须按项目页核实。SINGLE-SOURCE
  • 无「生成模型在古诗朗读上的横向评测」。所有模型的中文古诗朗读质量均缺第三方可复现数据，最终只能靠本项目小样本听测。证据缺口
  • 逐字平仄控制仍是无解项。所有商用 API 与开源模型均无逐字音高/时长显式控制，Intoner 未开源。一致确认

结论

  • 商用 API 已可满足需求：男声 + 情感 + 句级抑扬顿挫现成可用，Top 3 为火山擎苍 2.0 / Azure（poet・lonely）/ 阿里 CosyVoice v3.5。
  • 本地路线首次成熟：Qwen3-TTS（Apache-2.0、描述式音色、指令控制）是本地首选。
  • 诗歌专用仍是空白：Intoner 不可用；MCGA 是唯一大规模授权语料（朗读非吟诵）；CosyVoice「李白」诗词音色预设值得立即实测。
  • 法律红线明确：克隆真人声音须参照肖像权规则，一律不碰。
  • 链路结论不变：生成器给「情感 + 男声」，韵律后处理给「逐字平仄」，二者叠加才是完整方案。
