# 水墨诗画 · 工程目录

三首绝句（江雪 / 早发白帝城 / 静夜思）的「格律 → 画法 → 意象 → 动画 → 配音」全链路工程。
本文件说明目录如何组织、数据如何分类、脚本如何解析路径。

## 组织原则

**两层分类。** 第一层「角色域」决定文件给谁看、干什么用（研究 / 设计 / 数据 / 代码 / 交付 / 构建）；
第二层「子系统前缀」决定文件属于哪条链（`o1` `o2` `o3` `d1` `d2` `voice`）。
先按角色域落位，再按子系统归类，避免「既属于研究又属于数据」的归属纠结。

**数据三分类。**

| 分类 | 含义 | 可否重算 |
|---|---|---|
| `source` | 冻结输入（题集 / gold / 词典 / 语境资料） | 否，人工维护 |
| `derived` | 由 source 推导的中间数据（韵书 / 技法 / 意象 / 负节点） | 是 |
| `runs` | 一次跑批的运行产物（回归 / 覆盖 / 探针 / 评分） | 是，每次跑覆盖 |

**路径解析约定。**
- Python：`ROOT` 上溯到仓库根，其余一律 `os.path.join(ROOT, ...)`
- Node：`ROOT = path.resolve(__dirname, '..', '..')`；读数据走 `datapath()` 三级回退（source → derived → runs）
- 交付包内的相对引用由 `build/assemble.py` 装配时改写（如音轨 → `samples/voice/`），源文件保持 canonical 路径

## 约定

- pipeline 页内的 D2 参数单元格带 `data-d2="<路径>"` 溯源属性，并内嵌 `<script id="d2-snapshot">` 供离线复核
- 场景几何单一真源：动画 `<pid>-cam` 的命名元素几何冻结为 `data/source/scene/<pid>.json`（`bd` 白帝城 / `jx` 江雪 / `jys` 静夜思）；全链路 STEP5 线稿 / STEP6 静帧
  由 `build/scene_render.py` 从该文件渲染注入（标记块 `<!-- SCENE:<pid>:draft|ink -->`）。`build/verify.py` 断言
  「动画 ↔ 场景数据 ↔ 全链路」三方逐值一致，任一变化即判漂移；改动画后跑 `--extract` 重冻、`--write` 重渲。
- 几何一致 ≠ 处方兑现。`build/scene_assert.py` 从冻结场景量取画面属性（有效墨浓度 eff / 柔度 σ·位移 / 人高占比），
  与 D2 现算的 `role` / `water` / `size` 对账：焦点须全场最深（或最亮）、含水档须匹配浓淡与柔度、人物 size 须落在四档区间。
  防「模型算了、画面没照做」；`build/verify.py` 已纳入该断言。
- `build/assemble.py` 幂等，重复运行结果一致；`--check` 以字节比对判定漂移
- 题款字体单一真源：`dist/animation/fonts/*.woff2`（七款子集，均含三首题诗 69 字；生成/校验见 `build/font_subset.py`）。
  动画以 `@font-face` 引用、系统楷体兜底，跨平台一致；`build/assemble.py` 按同相对路径 `fonts/` 复制入包。
  书体谱系与定档（正文按诗的 V/A/T 档，落款按「文正款活」升一档用行书）：
  - `PoemKai` 楷·温润（霞鹜文楷 LXGW WenKai TC，SIL OFL 1.1）— 全局兜底
  - `PoemMaShan` 楷·开张（马善政毛笔楷 Ma Shan Zheng，SIL OFL 1.1）— 白帝城 / 静夜思正文
  - `PoemLongCang` 行楷·瘦劲（龙藏 Long Cang，SIL OFL 1.1）— 江雪正文
  - `PoemZhiMang` 行·流动（志莽行书 Zhi Mang Xing，SIL OFL 1.1）— 三首落款
  - `PoemCao` 草·狂放（柳建毛草 Liu Jian Mao Cao，SIL OFL 1.1）— 谱系占位，补高唤醒情感区（怒/惧/惊），三首未用
  - `PoemDaoLi` 隶（阿里妈妈刀隶体 AlimamaDaoLiTi，作者声明免费商用+可嵌入，非 OFL）— 谱系占位，三首未用
  - `PoemSeal` 篆（敬峰中山王篆 JFZSKSealScript，SIL OFL 1.1，依 OFL §3 改名）— 印章，仅「江雪白帝静夜」6 字
  书体谱系「篆隶楷行草」齐备；书体的收放 ↔ 唤醒 A、同体冷暖 ↔ 效价 V，映射见 `docs/research/font_element_data_mapping.html` §2。
  字符集 = 三首题诗用字 ∪ 落款（诗人名 柳宗元/李白）∪ 印章用字 ∪ 诗题用字（共 69 字）。
  改动用字后跑 `python build/font_subset.py --fetch` 重取、`--check` 校验（覆盖字符集 + 被动画引用 + 全链路页内嵌印章篆体）
- 题诗落款：由动画 `cfg.poem.author` 驱动，作「末句左邻新列、小字（正文 0.58 倍）、与末句下齐」，
  于末句写毕后逐笔写出（`-poemink` 组内，随题诗一同被 `hidePoem` 隐藏，不影响 O1 场景评估）
- 题诗「真笔顺书写」单一真源：`dist/animation/strokes.js`（`window.POEM_STROKES`，64 字 / 3 字体）。
  每字 = 字形轮廓 `<path>` + 逐笔中线遮罩（笔锋带），按笔顺以 `stroke-dashoffset` 展开，末笔走完即字形本体。
  笔顺与中线取自 `hanzi-writer-data@2.0.1`（源自 Make Me a Hanzi，**Arphic Public License**），字形取自持字体子集；
  二者在 `build/stroke_data.py` 合并（中线换算到设计单位 `upem=1000` 并按 RDP 简化，逐笔带宽由轮廓边界点归属最近中线算出），
  含覆盖护栏（边界点到最近笔锋带的外凸 ≤ 0，即无空洞、不串笔），已纳入 `build/verify.py`。
  数据缺失（未加载 / 缺字）时自动降级为旧的矩形揭示，不影响页面可用性。
- 印章篆体同时以 base64 内嵌进三张全链路页（`python build/font_subset.py --embed`，幂等）：
  全链路页为自足单文件，不内嵌则页内 `font-family="PoemSeal"` 会静默回退宋体、与动画的篆书印章不一致；
  源字库经 jsDelivr 镜像取回（`build/font_subset.py` 内 `FILE_FONTS[0].urls`），字体为极瘦长「铁线」风格，印面随字形取长方（26×44）
- D3 音乐层单一真源：`data/source/d3/<pid>_music.json`（声法表：调式 / 配器 / 板式 / 结构 / 连贯 + 逐字音事件）。
  `src/music/music_render.py` 只读此表、不自行编曲，渲染 `dist/audio/music/<pid>.wav`。六轴对应研究报告
  `docs/research/music_expression_elements.html` §2/§3：调式取 D2 的 V/A/T 档——
  江雪＝羽（水/冬 · 古琴 + 箫偶入 · 散板），早发白帝城＝徵（火/夏 · 笛主奏 + 古琴点缀 · 快板/流水板），
  静夜思＝宫（土/长夏 · 箫为主 + 古琴轻点 · 一板三眼）；
  轴 F（留白 / 静默）在本层取「不设长静默」（见下）。
  三条硬约束：① 音乐轨时长 = 配音实测总时长（同一把「尺子」，防漂移）；② 逐字起音按配音 `syllables[].frames`
  作权重分配，挂在同一条行时序上；③ **全曲连贯**——每个音「响到下一次起音 + overlap」（`rules.ring_max_s / ring_min_s /
  note_overlap_s`），行间气口由前音余响 + 「气口低散音」（`breath_events`）贯入，仅曲末留 250–320ms 自然收尾渐隐。
  主奏为吹管时其 `events[]` 带 `voice`：**笛走真实干声**（`sampler.DiziBank`，Hypnotriod / Freesound pack 21613, CC0 1.0，
  落在 `data/source/d3/dizi/` + `manifest.json`，25 条实测 f0 395–1554 Hz 即 G4–G6），**箫仍为加性合成** `xiao_note`
  （未找到许可可再分发的免费箫实录）。古琴只作 `guest_events` 点缀（代琵琶 / 筝），走采样播放器。
  原「句末顿（80ms 释放 + 混响 150ms 收湿）+ 静默段」已取消：默认「纯音乐」模式下，配音的行间气口不再是
  音乐留白的理由（实测原静默占 31.7%、最长 1.76s，听感为「断」）。动态由 `mix.soft_clip` 分档：江雪 1.0（极窄）、
  静夜思 0.6（中）、白帝城 0.4（宽，保留快板的开阔动态）。
  `--check` 断言时长 / **最长静默 ≤ 0.30s**（100ms 窗、−40 dBFS 门限）/ 峰值 / 波峰因数 + 「处方兑现」（音高落点、
  走手音真滑）+ 「音色护栏」，`--selftest` 以负向扰动（抹掉一段）证明连续性断言可失败（非空断言）。
  音色护栏（2026-10-05 升级为采样版）：音色源由合成（Karplus-Strong 拨弦 / 加性泛音）换为
  **GuqinSonGest 真实古琴干声**（CC BY 4.0，Zenodo 14962054；落在 `data/source/d3/samples/` + `manifest.json`，
  仅取接触麦通道 = 干声）。播放器 `src/music/sampler.py` 负责就近取源、变调（>12 半音回退全池并登记 `fallback_log`）、
  散/泛/按分色、绰注走手音（真实滑音干声）、吟猱（真实颤吟，仅近音高用）。护栏口径随之从「音头上升时间」
  升级为「与参考采样的频谱包络距离」：各音色档在源音高零变调渲染后，24 带对数频谱包络（去均值）与参考干声的
  RMS 距离须 ≤ 3.0 dB（实测 0.08–0.16 dB；白噪「滴答」23.5 dB 被判失败）。改采样的动因：合成拨弦音头是宽带瞬态，
  听感即「电子滴答」，多次参数修补仍未根除（详见 `_archive/_scratch_diag_2026-10-05/` 的盲听与频谱诊断）。
  笛同样因「不像笛子」换实录：原加性合成笛实测谐波滚降仅 −6.9 dB/oct、质心 2024–2586 Hz、无音内漂移；
  实录为 −13.6 dB/oct、质心约 5004 Hz、气声 −16.5 dB、含 ±0–11 音分自然漂移。`dizi_timbre_checks` 钉死该回归
  （实录包络距离 0.05–0.09 dB，合成笛 16.42 dB，护栏具区分力）。`dizi_note` 保留为显式 fallback 与诊断对照。
  笛的音高断言用「同检测器残差」口径而非直接比 Hz：自相关对真实吹奏有系统偏置（源样本本身被读高 +38～+133 音分），
  故比对「渲染色 vs 同一源样本原样」的变调残差（实测 +0.6～+3.1 音分），并在 `--selftest` 中以「错 1.5 半音取源」
  证明该断言非空（残差 −47.2 音分被判失败）。
- **吹管主奏按乐句连奏**（`rules.legato` + `rules.legato_voice`）：逐字独立起音 + 独立释放在 0.3s 间隔下
  会把一句变成 7 声风琴。改为按气口切乐句、句内只换指不重新起音（真实竹笛换指约 30–50ms，笛取 42ms、
  箫按孔较缓取 55ms），字头留轻微吐字起伏、入声处加重做出「顿」。韵脚并入前乐句且禁止 1 字乐句，

  画面以**音乐时钟**为准；点开即启用吟诵、音乐随之闪避、画面改用**人声时钟**（两者共用同一时间轴，切换不错位）。
  无音乐轨时恒为人声（`ink_animations.html` 内 `voiceOn = !cfg.music`）。
- **音频引用带内容哈希版本戳**：`ink_animations.html` 的 voice/music 引用写成 `<name>.wav?v=<md5 前 8 位>`，
  由 `src/music/stamp_audio_ver.py` 生成（幂等，`--check` 已纳入 `build/verify.py`）。音频重渲后**必跑该脚本**，
  否则 `file://` 下浏览器会继续播缓存里的旧 wav——「主奏修好了却仍听不到」正是此因（《静夜思》北箫修复后用户仍只听到筝）。
- 输入端护栏（D1 音韵 / D5 语境 schema / D6 情感词表 / O2 虚实阈值 G13）已纳入 `build/verify.py`，改动后随全链路体检一并跑
- O2 虚实阈值单一真源：`conc → 实写/虚写/不可实写` 的阈值冻结在 `data/source/o2_gate.json`，`o2_imagery.mjs` 读此文件、不写死；
  `--check` 断言「冻结值 = gold 最大裕度中点」「阈值落可行区间」「gold 分类全对」，并做「推过界必错」证伪；样本增补后跑 `--calibrate` 重标定
- `dist/三首诗歌交付/index.html` 手工维护，装配不触碰
- `_archive/` 只增不删，用于回溯迁移前后的差异（含退役的临时脚本与 scratch 音频等）
- 仓库根 `.gitignore` 忽略 `__pycache__/`、`*.pyc` 与宿主生成的 `.trae-html-share-packages/`

## 多人协作约定（两台PC）

本仓库按「**代码入库、素材本地持有**」原则组织：Git 里只跟踪**声法表 JSON、渲染代码、
页面 HTML/JS/CSS、文档**；音频素材与渲染产物不入库。仓库当前约 307 个文件 / 7.3 MB。

### 为什么不把音频放进Git

采样素材（古琴 / 笛 / 箫 / 扬琴 / 古筝 / 曲笛）合计约 200 MB，渲染产物与位图另有 40 MB+
。音频一旦入Git，历史会永久留存，即使后来删除也无法瘦身，且两台PC 同步极慢。

### 新PC 的初始化步骤

```bash
git clone <仓库地址>
# 关键：素材不在仓库里，需另行拷贝 data/source/ 下的采样目录：
#   data/source/d3/{samples,xiao,dizi,guzheng,khim,qudi}/
# 这些目录内 *.wav 已被.gitignore 排除，但 manifest.json 已入库，
# 可用它核对素材是否齐全（文件名 + 校验信息）。
pip install numpy scipy soundfile
python build/verify.py       # 素材就位后跑一次，确认环境可用
```

### 协作约定

- **声法表是单一真源**：`data/source/d3/<pid>_music.json`。改配器 / 音区 / 混响
  都只改这里，`src/music/music_render.py` 只读不编曲。切勿在渲染器里写死编曲参数。
- **音频产物不同步**：各自跑 `python src/music/music_render.py --pid <pid>` 生成，
  **不要提交 `dist/audio/`**。若需交换音频成品，用网盘或直接传文件。
- **改动后必跑**：`python build/verify.py`（全链路体检）+ 若重渲了音频，
  `python src/music/stamp_audio_ver.py`（否则页面会继续播缓存旧音频）。
- **分支建议**：一人一分支（如 `main` / `daughter-exp`），改完合并。
  声法表改动若涉及配器，建议在commit message 里写清「改了哪首、哪个音区」。
